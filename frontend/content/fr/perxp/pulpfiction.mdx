# PulpFiction.fr : collection et chatbot IA

## Contexte

[PulpFiction.fr](https://pulpfiction.fr) présente et administre une collection d'objets consacrés au film, avec une galerie publique, des fiches détaillées et des liens d'affiliation. J'ai développé l'application complète, puis un second service IA ([Replic](https://github.com/ticoraph/Replic)) permettant de converser avec Jules, Vincent, Mia, Marsellus, Butch ou Winston Wolf.

Le projet associe ainsi deux besoins distincts : exploiter un catalogue éditorial en production et construire un personnage conversationnel capable de respecter le style du film sans inventer ses faits.

## Problème

La galerie devait rester rapide et publique, tout en réservant les opérations de création, modification, suppression, visibilité et réordonnancement à un seul administrateur. Comme App Runner ne dispose pas ici d'un ingress privé, la protection ne pouvait pas reposer sur une route simplement masquée dans le frontend.

Pour le chatbot, un modèle généraliste connaissait le film mais ne reproduisait pas de façon stable la voix de chaque personnage. Le fine-tuning pouvait renforcer le style, mais pas garantir la factualité; il fallait donc séparer personnalité apprise et connaissances retrouvées dans un corpus documentaire.

## Solution

J'ai construit la galerie en React et TypeScript, avec une API FastAPI et une base PostgreSQL. Les lectures sont publiques. Les écritures exigent un secret `X-Admin-Secret` que le navigateur ne connaît jamais : Cloudflare Access protège la route d'administration par OTP et un Worker injecte le secret avant de relayer la requête vers l'API.

Pour le chatbot, j'ai extrait 1 181 dialogues du scénario, traduit le corpus en français, construit 165 paires issues du script et généré 1 200 paires synthétiques. Le split final contient 1 229 exemples d'entraînement et 136 de validation. J'ai spécialisé `Llama-3.1-8B-Instruct` par QLoRA, puis ajouté un RAG pgvector sur des analyses, chronologies, citations et fiches de personnages. FastAPI assemble le persona, l'historique et les quatre passages les plus proches avant de lancer la génération en streaming.

## Architecture

```text
Navigateur
   │
Cloudflare + Cloudflare Access
   │
   ├─ S3 / CloudFront ── React + TypeScript
   │
   └─ Worker ── FastAPI catalogue ── PostgreSQL RDS
                    │
                    └─ proxy SSE vers le service chatbot
                                  │
                         FastAPI RAG / App Runner
                           ├─ pgvector
                           └─ vLLM / Modal GPU L4
                                  │
                         Llama 3.1 + adapter LoRA HF
```

Les deux dépôts restent indépendants. Le site ne contacte jamais directement Modal et ne transmet pas la clé du microservice au navigateur; son backend relaie le flux SSE et les sources documentaires.

## Déploiement

Le frontend de la collection est compilé avec Vite puis publié sur S3 derrière CloudFront et Cloudflare. Le backend Docker est construit dans GitHub Actions, poussé dans ECR et déployé sur AWS App Runner. Les objets sont stockés dans PostgreSQL RDS; les secrets sont fournis par l'environnement et AWS SSM.

Le service chatbot suit une chaîne distincte : les jobs QLoRA peuvent être lancés sur SageMaker ou Vertex AI, les runs sont suivis dans Weights & Biases et l'adapter est publié sur Hugging Face Hub. vLLM le sert sur un GPU L4 Modal avec `min_containers=0`; les poids sont conservés dans un volume pour réduire le cold start. L'API RAG est déployée séparément sur App Runner.

## Impact

La collection est administrable sans système de comptes publics : les visiteurs disposent d'une galerie responsive et l'administration conserve un CRUD complet, le contrôle de visibilité et l'ordre d'affichage. Le filtrage à l'edge et le secret injecté côté serveur ferment le contournement direct par l'URL App Runner.

Le pipeline IA est opérationnel de la création du dataset au serving : corpus français versionné, entraînement cloud reproductible, adapter portable, retrieval pgvector et génération streamée. Le proxy et le client SSE sont intégrés au site; la page publique du chatbot reste toutefois présentée comme en cours de finalisation, ce qui distingue clairement le service technique de son ouverture aux visiteurs.

## Apprentissage

J'ai appris à séparer les responsabilités de sécurité entre navigateur, edge et backend. Une route non référencée n'est pas une protection; le contrôle d'écriture doit être imposé par le serveur et le secret ne doit jamais entrer dans le bundle frontend.

Le chatbot m'a également montré la complémentarité entre fine-tuning et RAG : QLoRA façonne le ton et les habitudes de réponse, tandis que la recherche documentaire apporte les faits. Le déploiement scale-to-zero m'a enfin obligé à arbitrer coût, cold start et expérience utilisateur.
