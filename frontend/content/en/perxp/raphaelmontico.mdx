# RaphaelMontico.fr: AI-native portfolio

## Context

[RaphaelMontico.fr](https://raphaelmontico.fr) presents my background, experience, and projects in French and English. I chose to make it more than a showcase: the site's actual content powers a semantic search API and an assistant capable of answering visitors' questions about my profile.

The project serves as an ongoing demonstration of a production RAG architecture, from editing MDX pages to streaming a response and observing it in Langfuse.

## Problem

The site needed to remain fast, indexable, and available independently of the AI backend. At the same time, the chatbot needed a vector database, an embedding model, and an LLM—components incompatible with a simple static export.

I also needed to maintain two languages without manually duplicating every change, avoid unnecessary re-ingestion, and understand RAG behavior. With an SSE response, the OpenTelemetry trace must remain attached throughout the stream, even after FastAPI's initial return.

## Solution

I kept French as the editorial source in MDX files. A checksum registry detects modified pages; a script translates only pending content using OpenAI and checks that the collections are in parity. Next.js then generates a fully static bilingual frontend.

A separate pipeline cleans the pages, splits them into chunks, calculates 768-dimensional OpenAI `text-embedding-3-small` embeddings, then synchronizes them to PostgreSQL/pgvector. FastAPI exposes `/api/search` and `/api/chat`. For chat, the question is vectorized, the five closest passages in the requested language are added to the prompt, and GPT-6 Luna returns tokens over SSE along with sources and latency and usage metrics.

## Architecture

```text
French MDX ── checksums ── OpenAI translation ── English MDX
      │                                         │
      ├──────────── Static Next.js ─────────────┘
      │                    │
      │               S3 + CloudFront
      │
      └─ ingestion → chunks → OpenAI embeddings
                                  │
                             PostgreSQL/pgvector
                                  ▲
Visitor → FastAPI → retrieval → GPT-6 Luna → SSE
                    └──────── Langfuse / OpenTelemetry
```

The frontend remains usable if the AI API is unavailable. The interface for embeddings is separate from the one for the LLM, allowing both responsibilities to evolve without changing the ingestion pipeline or chat contract.

## Deployment

GitHub Actions checks the frontend and backend for every proposed change. On the main branch, the exported frontend is synchronized to S3 and served by CloudFront; the Docker backend is deployed separately on AWS with App Runner/API Gateway and accesses PostgreSQL.

An ingestion workflow is triggered when MDX content or indexing code changes. Alembic migrations version the schema. OpenAI and Langfuse keys stay on the backend; OpenAPI documentation can be disabled in production, and body-size and rate limits protect public routes.

## Impact

A single content source now powers three use cases: portfolio pages, semantic search, and chatbot responses. The site can be browsed as usual or queried in natural language, with the sources used shown alongside the answer rather than an answer that cannot be verified.

Langfuse traces the request, retrieval, and generation, while the final event exposes the model, tokens, and retrieval/generation time. This observability makes it possible to relate quality, latency, and cost without turning the static frontend into an application that depends on the backend.

## What I learned

I learned to treat content as versioned data: translation, indexing, and deployment must respond to its changes deterministically. The checksum registry avoids full processing runs and makes discrepancies between languages visible.

Propagating OpenTelemetry context through an SSE generator also exposed me to a practical asynchronous observability problem. A useful trace must follow the response through to the last token, not stop when FastAPI returns the `StreamingResponse` object.
